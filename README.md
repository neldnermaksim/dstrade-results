# DSTrade — Результаты

Публичный раздел с результатами и аналитикой алгоритмов DSTrade: сводная доходность по всем реальным счетам платформы — стратегии, монеты, режимы закрытия, стадии скринера, месяцы и дни.

Это **фронтенд-шаблон на демо-данных**. Интерфейс полностью готов. Данные генерирует детерминированный генератор, а реальные подключаются заменой одного слоя (см. «Подключение реальных данных»).

- Стек: React 19, TypeScript, Vite, React Router. UI-библиотек нет, графики — собственный SVG, иконки — `lucide-react`.
- Дизайн повторяет публичную часть dstrade.io: токены `.public-site`, классы `pub-*`, шрифт Manrope, ритм секций «01 / …», кнопки, сегменты, FAQ, подвал. Панели, KPI, бары, календарь и бейджи стадий повторяют «Статистику» и «Скринер» кабинета.
- Адаптив: точки перелома 1280 / 1024 / 720 px, как на основном сайте. Проверено на 375 px без горизонтальной прокрутки.
- Доступность: навигация с клавиатуры, `focus-visible`, `aria-*`, зоны нажатия от 44 px, `prefers-reduced-motion` и кнопка «Пауза анимации».

## Страницы

| Адрес | Что на странице |
| --- | --- |
| `/` | **Обзор.** Индекс DSTrade против BTC; ключевые показатели («Сделок закрыто», «Доля прибыльных», «Средняя сделка» и др.); причины закрытия; карточки стратегий; таблица «месяц × стратегия / монета / стадия»; спот против алгоритма; лидеры месяца и прибыль портфеля Топ-10/20/30; календарь прибыли и рекорды; калькулятор «Что было бы, если»; FAQ. |
| `/strategies` | **Стратегии.** DCA · Manual (LONG / SHORT / все) и DCA · Auto: результат и график, режимы закрытия (Ранний / Обычный / Агрессивный / Overkill), стадии скринера (PUMP, RIDE, RUN, CRASH, FLIP, DUMP, EARLY), глубина усреднений по весам, причины закрытия, биржи, таблица по месяцам. Фильтры хранятся в URL: `?s=auto&p=365d`, `?s=manual&dir=LONG`. |
| `/coins` | **Монеты.** Как вкладка «Портфель» скринера: состав Топ-10 / 20 / 30, LONG / SHORT, период или месяц, поиск, сортировка, топ-3 месяца, вид «По месяцам». Нажатие на строку открывает карточку монеты (помесячно алгоритм против спота, лучший и худший месяц). Параметры в URL: `?coin=BTC&dir=SHORT&tier=10&m=2026-08`. |
| `/reports` | **Отчеты.** Архив месяцев с индексом, сделками, долей прибыльных и лучшей монетой. |
| `/reports/2026-08` | **Отчет за месяц.** Аналог месячного листа таблицы доходности: «Актив топ-15 / Трейдов за месяц / Прибыль за месяц, %», «Топ-3 по прибыли за месяц», «Прибыль портфеля, % за месяц», стратегии, стадии, календарь дней, рекорды. Есть «Поделиться» и выгрузка в CSV. |
| `/methodology` | **Методика расчета.** Оформлена как правовые страницы dstrade.io: что входит в статистику, как считается доходность, термины, риски. |

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # проверка типов + сборка в dist/
npm start          # раздача dist/ (как на Railway), порт из $PORT или 3000
```

Нужен Node.js 22.12 или новее (см. `.nvmrc`).

## Деплой на Railway

1. В Railway: **New Project → Deploy from GitHub repo →** выберите этот репозиторий.
2. Railway сам определит Node-проект. Команды уже прописаны в `railway.json`: сборка — `npm run build`, старт — `npm start`.
3. В **Settings → Networking** нажмите **Generate Domain** или подключите свой домен.
4. Переменные окружения (необязательно, значения по умолчанию подходят), вкладка **Variables**:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `VITE_APP_ORIGIN` | `https://dstrade.io` | Адрес основного сайта для ссылок «Войти», «Регистрация», «Тарифы» |
| `VITE_DATA_SOURCE` | `mock` | `mock` — демо-данные, `api` — реальный бэкенд |
| `VITE_API_BASE` | `/api/v1/public/results` | Базовый адрес публичного API |
| `VITE_COMMUNITY_URL` | ссылка на Telegram-сообщество | Кнопка «Сообщество в Telegram» |
| `BASE_PATH` | `/` | Префикс, если раздел живет внутри сайта, например `/results/` |

Переменные `VITE_*` подставляются при сборке, поэтому после их изменения нужен redeploy.

`npm start` раздает `dist/` через `serve` в режиме SPA: любой путь отдает `index.html`. У ассетов кэш на год (в именах файлов есть хэш), у `index.html` — `no-cache`.

## Подключение реальных данных

Страницы получают данные только через объект `api` из `src/api/index.ts`. Формат ответов описан в `src/api/types.ts` — это и есть контракт. Примеры ответов (сгенерированы из демо-данных, массивы укорочены) лежат в `docs/api-examples/`.

Чтобы включить реальные данные, задайте `VITE_DATA_SOURCE=api` и реализуйте на бэкенде эндпоинты:

| Функция | Запрос | Ответ |
| --- | --- | --- |
| `api.summary` | `GET {BASE}/summary?period=30d` | `Summary` |
| `api.equity` | `GET {BASE}/equity?period=30d` | `EquityPoint[]` |
| `api.segments` | `GET {BASE}/segments?period=365d` | `SegmentStat[]` |
| `api.monthly` | `GET {BASE}/monthly?year=2026&by=segments\|coins\|stages&direction=LONG&limit=15` | `MonthlyMatrix` |
| `api.coins` | `GET {BASE}/coins?tier=30&direction=LONG&period=30d` или `&month=2026-09` | `CoinStat[]` |
| `api.coin` | `GET {BASE}/coins/BTC` | `CoinDetail` |
| `api.top3` | `GET {BASE}/top?month=2026-09` | `TopCoin[]` |
| `api.strategy` | `GET {BASE}/strategies/manual?direction=ALL&period=365d` | `StrategyDetail` |
| `api.stages` | `GET {BASE}/stages?period=30d` | `StageStat[]` |
| `api.calendar` | `GET {BASE}/calendar?from=2026-03-01&to=2026-09-26` | `DayStat[]` |
| `api.records` | `GET {BASE}/records?period=90d` | `Records` |
| `api.spot` | `GET {BASE}/spot?months=6` | `SpotComparison` |
| `api.months` | `GET {BASE}/reports` | `MonthSummary[]` (новые сверху) |
| `api.report` | `GET {BASE}/reports/2026-08` | `MonthReport` |
| `api.series` | `GET {BASE}/series` | `SegmentMonthSeries[]` (для калькулятора) |

Соглашения:

- Проценты — числа: `6.35` означает +6,35%. Считаются к сумме, выделенной боту, без подушки, после комиссий бирж и фандинга. Комиссия платформы не вычитается (ее учитывает калькулятор).
- Даты — `YYYY-MM-DD`, месяцы — `YYYY-MM`. Для текущего месяца значения частичные (на вчера).
- Только реальные счета, демо не участвуют. Сделка считается в день закрытия корзины.
- Если удобнее ходить в API иначе (другие пути, GraphQL, SSR), меняется только `src/api/index.ts`, страницы трогать не нужно.

Когда реальные данные подключены, папку `src/api/mock/` можно удалить. Тогда уберите и плашку «демо-данные» в окне индекса: она показывается только при `VITE_DATA_SOURCE=mock`.

## Структура

```
src/
  api/              контракт (types.ts), точка доступа (index.ts), генератор демо-данных (mock/)
  components/
    layout/         шапка, подвал, логотип (разметка из шапки dstrade.io)
    ui/             сегменты, селект, подсказки, бейджи стадий и направлений, KPI, дроуэр, состояния
    charts/         SVG-графики: площадь, колонки, спарклайн, календарь, теплокарта, бары
  content/          словари: стадии, режимы закрытия, причины, стратегии, монеты портфеля
  lib/              форматирование (ru-RU, «−», «1 725,49 $»), даты, хуки
  pages/            страницы и секции главной (pages/overview/)
  styles/           tokens.css — все цвета и радиусы; layout / components / charts / pages
public/
  landing/          логотипы бирж с dstrade.io
  coins/            иконки монет (cryptocurrency-icons, CC0); для остальных — фирменный цвет и буквы
```

## Что стоит проверить разработчику

- **Описания режимов закрытия** (`src/content/dictionary.ts → EXIT_MODES`). В кабинете есть только названия («Ранний / Стандартный / Поздний режим закрытия позиций») и описание Overkill. Остальные описания — черновые формулировки.
- **Причины закрытия** «Корзина» и «Тейк-профит»: описания в том же файле тоже стоит сверить с логикой бота.
- **Уровни риска стратегий и стадий** (`RISK`, `STAGES[*].risk`) — предложение, не данные.
- **Индекс DSTrade** — средневзвешенный по выделенным суммам результат сегментов. Если на бэкенде удобнее другой агрегат, поменяйте формулировки в `pages/Methodology.tsx` и подсказках.
- Все денежные итоги («Итог пользователей», оборот) можно скрыть, если публиковать абсолютные суммы не нужно: это отдельные KPI в `pages/overview/Hero.tsx` и `KeyStats.tsx`.
